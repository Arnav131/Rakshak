**Rakshak** (रक्षक — *"The Guardian"*) is a full-stack, AI-driven railway predictive maintenance platform that monitors track health in real time, detects anomalies before they become failures, and empowers controllers with actionable safety intelligence.

*Built with production-grade architecture. Deployed on Render via Docker.*

## ✨ Features

### 📊 Operations Dashboard
> Real-time command center — no mock data, everything pulled live from the database.

- **KPI Cards** — active alerts, open tickets, sensors online, track sections monitored
- **Alert Feed** — top 5 critical/warning alerts with severity badges
- **Health Breakdown** — track section health derived from real alert aggregates
- **Sensor Trends** — Chart.js time-series charts + recent readings table
- **System Summary** — doughnut chart, operator activity log, live clock

### 🗺️ Interactive Railway Map
> Dark-themed Leaflet.js map of the entire Indian rail network.

- Station markers color-coded by health status
- Real track section geometry polylines
- Active alerts & open tickets overlaid on the map
- **Live train simulation** — animated markers moving along routes in real time
- Click-through popups linking to alert/ticket details

### 🚨 Alert Management
- Full alert list with severity badges — `critical` · `warning` · `caution` · `info`
- Filter by severity and status
- Alerts auto-generated by the AI pipeline when anomalies are detected
- Escalation tracking and acknowledgment workflow

### 🎫 Ticket Management
- Maintenance ticket board with priority/status filtering
- Live search via `/tickets/api/search/`
- Tickets linked to assets and track sections
- Status change audit trail (`TicketStatusLog`)

### 🤖 Live AI Simulation *(Staff Only)*
> **This is the crown jewel.** Generates fresh data on every run — never preloaded.

1. Pick any source → destination from 120+ seeded stations
2. **Dijkstra shortest-path routing** over real track sections in the database
3. An LLM generates a brand-new 16-reading synthetic IoT journey for that route
4. **Fallback chain**: Gemini → Grok → Anthropic → OpenAI → Ollama → Physics RNG
   *(works even with zero API keys configured)*
5. All 16 readings streamed through the **real production prediction pipeline**
6. Pixel-art train animation + terminal-style log → verdict with alert level, fault type, anomaly score chart, and actionable suggestions
7. Automatically creates an Operational Readiness clearance case for that route

### ✅ Operational Readiness Control Center
> Departure-clearance workflow for routes and train services.

- Case dashboard with **Ready / Conditionally Ready / Hold** status counters
- Per-case safety checklist (route health, signal interlocking, schedule window…)
- Field sign-off per checklist item with role designation
- Controller decision submission
- Telemetry evaluation with live/simulated sensor data
- Full audit trail (`ReadinessAuditRecord`)

### 👷 Worker Patrol & Review
> Human field-inspection loop that complements the AI.

- Workers submit patrol reports rating **8 inspection categories**:
  Rail Condition · Track Geometry · Sleepers & Fastenings · Ballast · Drainage · Points & Crossings · Level Crossings · Formation & Earthwork
- Personal patrol history for workers; staff can preview all reports
- Admin review dashboard with weighted scoring and final decisions
- Role-gated access: `patrol_worker` vs staff

### 🔐 Role-Based Access Control

| Role                   | Access Level                                                                    |
| ---------------------- | ------------------------------------------------------------------------------- |
| **Controller** (Staff) | Full access — Dashboard, Map, Simulation, Readiness, Patrol Admin, Django Admin |
| **Patrol Worker**      | Dashboard, Map, Alerts, Tickets + Patrol submission                             |
| **Read-Only Viewer**   | Dashboard, Map, Alerts, Tickets — no control actions                            |

> Server-side enforcement on every restricted page and API — not just hidden menus.

## 🧠 AI Prediction Engine

A trained **6-model ensemble** inference pipeline — the core intelligence of Rakshak:

| Model                  | File                      | Purpose                                                                                      |
| ---------------------- | ------------------------- | -------------------------------------------------------------------------------------------- |
| 🔬 VAE Anomaly Detector | `vae_anomaly_detector.pt` | Deep-learning detection of abnormal sensor patterns                                          |
| ⚡ Failure Predictor    | `failure_predictor.pt`    | Future failure risk at 1h / 6h / 24h horizons                                                |
| 🔧 Fault Classifier     | `fault_classifier.pt`     | Classifies: rail fracture, thermal buckle, gauge widening, ballast washout, subgrade failure |
| 🌲 Isolation Forest     | `isolation_forest.joblib` | Classical ML anomaly detection                                                               |
| 📈 Statistical Detector | `stat_detector.joblib`    | Fast statistical deviation checks                                                            |
| 🎯 Meta-Classifier      | `meta_classifier.joblib`  | Fuses all detector scores into a single verdict                                              |

**How it works:**
- **64-reading rolling window** per sensor (sequence model)
- Monitors **4 physical signals**: ambient temperature, humidity, vibration RMS, gauge width
- Centralized severity thresholds keep alert severities consistent
- Predictions automatically create Django `Alert` records
- **Graceful rule-based fallback** when models/dependencies are unavailable

## 🚀 Quick Start

```bash
# Clone
git clone https://github.com/Arnav131/Rakshak.git
cd Rakshak

# Virtual environment
python -m venv .venv
.venv\Scripts\activate              # Windows
# source .venv/bin/activate         # Linux/macOS

# Install dependencies
pip install -r requirements.txt

# Configure
copy .env.example .env              # Set DATABASE_URL from Supabase

# Migrate & seed
cd backend
python manage.py migrate
python manage.py seed_master_data   # 120+ stations, zones, divisions
python manage.py seed_routes        # ~400 track sections + geometry
python manage.py seed_sensors       # sensor types + readings
python manage.py seed_demo_data     # alerts, tickets, maintenance teams
python manage.py seed_users         # controller / viewer / worker accounts

# Launch
python manage.py runserver
```

**Open** → [http://127.0.0.1:8000](http://127.0.0.1:8000)

## 🐳 Deployment

Rakshak is deployed on **Render** via Docker with zero-downtime deploys:

```
Dockerfile → pip install → collectstatic → docker-entrypoint.sh → migrate → gunicorn
```

**Production stack:**
- **Gunicorn** (3 workers, 120s timeout)
- **WhiteNoise** compressed static file serving
- **PostgreSQL** via Supabase with SSL + connection pooling
- Auto-configured `RENDER_EXTERNAL_HOSTNAME`, `CSRF_TRUSTED_ORIGINS`, `SECURE_PROXY_SSL_HEADER`
